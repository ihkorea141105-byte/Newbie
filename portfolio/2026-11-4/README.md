# 2026-11-04 | 응답 검증 모듈의 FastAPI 연동

## 오늘의 목표

11월 3일에 작성한 응답 검증 모듈을 기존 FastAPI 서버에 연결한다. 잘못된 모델 응답이 들어왔을 때 검증에 실패하고 기본 응답으로 처리되는지 확인한다.

현재 문서는 작업 계획이며, 실행 결과는 작업 후 기록한다.

## 프로젝트 방향

- **본 프로젝트 — 「대화 API 학습 예제」:** 우선 완성을 목표로 하며, 대화 API와 상태 관리의 기반을 구축한다.
- 공통 코드는 재사용하되, 응답 도우미별 설정과 구현 결과는 구분해서 기록한다.

- API 키는 서버 환경 변수로 설정하고 소스 코드나 실행 기록에 남기지 않는다.

## 2. 응답 검증 모듈 연결

`app.py`의 기존 `LLMResponse` 클래스 정의를 제거하고 다음 import를 추가한다.

```python
from response_validation import LLMResponse
```

기존 JSON 파싱, 응답 모델 생성, `ValidationError` 예외 처리는 유지한다.

연결하면서 다음 항목을 확인한다.

- [ ] 기존 코드에서 사용하는 필드와 새 검증 모델의 필드가 일치하는가?
- [ ] 상태은 `normal`, `focused`, `completed`만 허용되는가?
- [ ] 한 번의 예제 상태 점수 변화량은 정수 -5 이상 +5 이하로 제한되는가?
- [ ] 검증 실패 시 기본 응답 자체도 검증 규칙을 만족하는가?
- [ ] 상태에 따른 이미지 파일명 처리에 문제가 없는가?

상태 목록은 현재 코드의 검증 기준이며, 본 프로젝트의 응답 도우미 설정에 맞는지는 별도로 검토한다.

## 3. 검증 모듈 단독 실행

오늘 폴더에서 실행한다.

```bash
python response_validation.py
```

**예상 결과:** 8개 사례가 모두 PASS이며 마지막에 `8/8 검증 통과`가 출력된다.

이 단계는 응답 모델만 확인하며, FastAPI 서버나 실제 LLM 호출의 성공을 의미하지 않는다.

- [ ] 정상값과 경계값을 허용하는지 확인
- [ ] 허용하지 않은 상태와 범위 밖의 값을 거부하는지 확인
- [ ] 문자열 `"3"`과 불리언 `True`를 거부하는지 확인

## 4. FastAPI 연동 확인

기존 FastAPI·Groq 실행 환경에서 서버를 시작한다.

```bash
python -m uvicorn app:app --reload
```

브라우저에서 다음 주소로 접속한다.

```text
http://127.0.0.1:8000/docs
```

`POST /api/chat`의 요청 스키마에 맞게 값을 입력하고 대화를 요청한다.

- [ ] 정상 요청에 응답하는가?
- [ ] 주 응답, 보조 설명, 상태, 이미지 파일명 등이 기존 응답 형식대로 반환되는가?
- [ ] 예제 상태 점수 변화량이 검증 범위 안에 있는가?
- [ ] 반환된 대화 이력을 다음 요청에 넣었을 때 대화가 이어지는가?

실제 LLM이 우연히 잘못된 값을 반환하기를 기다리지 않는다. 오류 처리는 별도의 테스트에서 LLM 응답을 잘못된 상태나 범위 밖의 값으로 대체하여 확인한다. 단독 검증 성공과 API의 기본 응답 처리 성공을 구분한다.
