# 현 상황
현재 터미널 기반 1단계 테스트(Groq + Pydantic JSON 파싱)가 성공적으로 마무리된 만큼, 다음 목표는 이를 **웹 서비스 형태의 풀스택 앱**으로 확장하고 **GitHub에 채용 담당자용 포트폴리오**로 정돈하는 것입니다.

이 궤도에 맞춰 구체적으로 완성해 나갈 로드맵과 깃허브/문서 기술 적용 가이드입니다.

## 1. 메인 프로젝트 대화 API 학습 예제 개발 로드맵

| 단계 | 목표 | 상세 구현 내용 | 주 기술 스택 |
| --- | --- | --- | --- |
| **1단계** *(완료)* | **터미널 로직 검증** | Groq API 연동, Pydantic 이중 파싱(주 응답/보조 설명/상태/예제 상태 점수) 검증 | Python, Groq, Pydantic |
| **2단계** | **백엔드 API 서버 구축** | 터미널 로직을 REST API 엔드포인드로 전환 (`POST /api/chat`) | FastAPI, Uvicorn, CORS |
| **3단계** | **웹 UI 프론트엔드 제작** | 대화형 API UI 구축, 상태 라벨 라벨에 따른 실시간 일러스트 변경 | React (Vite) 또는 HTML/JS, Tailwind CSS |
| **4단계** | **대화 기억 & DB 연동** | 대화 세션 관리, DB 저장(SQLite/PostgreSQL), 슬라이딩 윈도우 + 비동기 요약 | SQLAlchemy / Peewee, SQLite |
| **5단계** | **클라우드 배포 & 서비스화** | 웹 프론트엔드와 백엔드를 외부에서 접속 가능하게 무료 서버 배포 | Vercel (Front), Render/Fly.io (Back) |

## 2. GitHub 포트폴리오 구축 & README 작성 가이드

개발자 채용 시 GitHub에서 가장 먼저 보는 것은 **코드 자체보다 잘 정리된 README.md와 커밋 이력**입니다. 바이브 코딩으로 작업하더라도 커밋 단위와 README 설명이 명확하면 실력을 대변할 수 있습니다.

### 깃허브 저장소(Repository) 구성 스펙

1. **커밋 메시지 규칙 (Git Commit Convention)**
* `feat: FastAPI 백엔드 대화 엔드포인트 구현`
* `fix: Groq JSON 응답 파싱 예외 처리 추가`
* `style: 상태 라벨에 따른 반응형 UI 일러스트 연동`


2. **README.md 필수 포함 항목**
* **프로젝트 한 줄 소개 & 동작 GIF/캡처:** 시각적으로 대화 API/대화형 API UI가 어떻게 작동하는지 보여주기.
* **시스템 아키텍처 다이어그램:** `React UI ↔ FastAPI ↔ Groq Llama3 ↔ SQLite DB` 데이터 흐름도 (Mermaid.js 활용).
* **엔지니어링 문제 해결 포인트 (가장 중요):**
* **1회 호출 이중 파싱:** 프롬프트 엔지니어링 및 Structured Output 활용으로 주 응답과 보조 설명을 1개 API 호출로 처리하여 토큰 비용 절감 효과는 측정 예정.
* **대화 세션 유지:** 슬라이딩 윈도우와 백그라운드 요약(Summarizer)을 통한 문맥 기억 구현.


* **Quick Start (실행법):** `.env.example` 설정 및 로컬 실행 명령어 정리.

## 3. 기업 제출용 문서 기술 (Word, PPT, Excel, HWP) 학습 방향

개발 직무에서 필요한 문서 능력은 컴활 등 자격증 위주 공부보다는 **프로젝트 명세서와 발표 자료 작성 경험**을 통해 쌓는 것이 직관적이고 효과적입니다.

* **GitHub Markdown (기본 1순위)**
* **목적:** 기술 블로그, README, API 명세서 작성.
* **배워야 할 요소:** 표 작성, 코드 블록, 이미지 링크, Mermaid 아키텍처 구조도.


* **Excel / Google Sheets (LLM 테스트 & 비용 산정)**
* **목적:** AI 모델별 performance 데이터 정리 및 비용 비교.
* **배워야 할 요소:** 기본 함수(`AVERAGE`, `COUNTIF`), 피벗 테이블, 조건부 서식, 라인 차트 (프롬프트별 토큰 소모량/응답 시간/파싱 에러율 정리용).


* **PowerPoint (면접 및 프로젝트 발표 장표)**
* **목적:** 면접용 프로젝트 포트폴리오 (3~5장 핵심 슬라이드).
* **배워야 할 요소:** 아키텍처 도식화, 핵심 기능 캡처 및 기술적 차별점 간결 정리 layout.


* **Word / HWP (기획서 & 기술 보고서)**
* **목적:** 요구사항 정의서, 기능 명세서 작성.
* **배워야 할 요소:** 개요 번호/다level 목록 설정, 목차 자동 생성, 표 테두리 스타일 적용.

## 4. 학습 및 개발 실행 순서

1. **FastAPI로 백엔드 엔드포인트 열기:** 기존 `main.py` 터미널 코드를 FastAPI 기반의 `/api/chat` API로 포팅합니다.
2. **간단한 HTML/JS 코드로 백엔드 통신 테스트:** 웹 브라우저에서 텍스트를 입력하면 FastAPI를 거쳐 주 응답/보조 설명/상태를 받아오는지 확인합니다.
3. **React 기반 웹 화면 입히기:** 응답 도우미 일러스트가 화면 중앙에 나오고 하단 대화창과 보조 설명 토글 버튼이 동작하도록 만듭니다.
4. **README 문서화:** 완성된 구조를 PPT 장표 3장과 GitHub README로 정리합니다.

현재 1단계 터미널 테스트 환경이 구성되었으니, **FastAPI를 활용해 백엔드 API 서버를 만드는 2단계 작업**부터 진행하는 것을 추천합니다. 백엔드 API 서버 구축용 코드 구조 작성을 먼저 시작해 볼까요?
