## 1. GitHub 리포지토리 구성 전략 (대표 프로젝트 중심)

잡코리아에 제출하는 GitHub 링크는 면접관이 소스 코드를 일일이 분석하지 않아도 **1분 안에 아키텍처와 구현력을 파악할 수 있도록 README**를 정돈해야 합니다.

### 대표 프로젝트 1: LLM 대화 API (메인)

* **Python 백엔드 구현 핵심**:
* **비동기 처리(Asyncio)**: `FastAPI`를 활용한 LLM API 비동기 호출 및 `Server-Sent Events(SSE)` 기반 실시간 응답 스트리밍 구현.
* **대화 기억 관리**: Redis 또는 DB 기반 세션 메모리 구성. 대화 누적 시 토큰 한계를 극복하기 위해 **최근 대화 요약(Summarizer) 로직** 적용.
* **프롬프트 엔진**: 응답 도우미 페르소나, 말투 규정, 선택지에 따른 분기 로직(State Machine) 구현.


* **README 필수 작성 요소**:
1. **시연 GIF / 스크린샷**: 대화 흐름, 선택지 작동 화면.
2. **시스템 아키텍처 구성도**: Client - FastAPI - LLM API - DB/Redis 흐름.
3. **기술 선택 이유**: Flask 대신 FastAPI를 선택한 이유 (비동기 I/O, Pydantic 자동 검증 등).
4. **성능/비용 고려 사항**: 프롬프트 토큰 절감률, 평균 응답 대기 시간 측정 데이터.


### 보조 프로젝트 2: 다른 프로젝트 (정리 및 유지보수)

* **강조점**: 완성된 웹/앱 서비스 경험 보유, 외부 API 연동 및 데이터 처리 능력.
* **README 필수 작성 요소**: 데이터 흐름(Data Flow), API 호출 처리 예외 로직, 배포 URL 또는 실행 방법.

## 4. 파이썬 & GitHub 역량 어필 핵심 체크리스트

1. **"파이썬을 쓸 줄 안다"가 아닌 "엔지니어링 코드를 짠다"를 보여줄 것**
* 단순 script 방식 작성이 아닌 `Class`, `Pydantic` 모델 정의, 예외 처리(`Try-Except` 예외 핸들러, API Retry 로직)를 적용한 깔끔한 코드 형태를 깃허브에 노출하세요.


2. **Git Commit 메시지와 브랜치 관리 기록 남기기**
* `feat: Add LLM SSE streaming endpoint`, `fix: Resolve Redis session memory leak`처럼 기능별 명확한 커밋 로그를 작성하세요. 면접관은 커밋 작업 내역에서 개발자의 성실도와 작업 방식을 평가합니다.


3. **GitHub Profile README 작성**
* 깃허브 메인 프로필에 **자기소개 + 메인 기술 스택 + 대표 프로젝트 바로가기 링크**를 고정(Pin)해 두세요.
