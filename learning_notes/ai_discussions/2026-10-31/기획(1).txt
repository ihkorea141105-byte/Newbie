## 당신에게 맞는 준비 방향

### 1순위: 웹 서비스를 직접 만드는 기본기

우선은 **웹으로 AI 대화 서비스를 완성하는 능력**을 목표로 하세요.

- **프론트엔드:** HTML, CSS, JavaScript → TypeScript → React
- **백엔드:** Python → FastAPI, REST API
- **데이터:** SQL, PostgreSQL
- **협업·배포:** Git/GitHub, Docker 기초, 클라우드 배포
- **AI 연결:** LLM API 호출, 대화 기록 관리, 응답 스트리밍, 비용·응답 속도 확인

처음부터 React와 Flutter, Unity를 한꺼번에 배울 필요는 없습니다. **React 웹앱 하나를 끝까지 만들고 배포한 뒤**, 모바일 앱이 필요하면 Flutter나 Android를 추가하는 편이 효율적입니다.

### 2순위: 좋아하는 서비스를 닮은 포트폴리오

대표작은 **“응답 도우미와 대화하며 이야기를 진행하는 LLM 대화 API”**으로 잡아보세요.

처음에는 다음 정도로 작게 완성하면 됩니다.

1. 응답 도우미와 대화하는 화면을 만든다.
2. LLM API를 연결해 응답을 보여준다.
3. 대화 기록을 저장하고 다시 불러온다.
4. 응답 도우미 설정과 시스템 설정을 넣어 말투·성격을 유지한다.
5. 선택지나 상태값으로 이야기의 진행을 바꾼다.
6. 긴 대화에서는 요약을 저장해 응답 도우미가 이전 일을 기억하게 한다.
7. 사용자가 대화를 삭제하거나 초기화할 수 있게 한다.

이때 단순히 “AI와 채팅됩니다”로 끝내지 말고, **응답 도우미 설정을 바꾸었을 때 응답이 어떻게 달라지는지, 대화 기억이 얼마나 잘 유지되는지, 응답 시간과 비용이 어느 정도인지** 보여주면 개발자로서의 판단력을 드러낼 수 있습니다.

기존 코드가 있다면 학습 자료로 정리합니다. README, 화면 설명, 데이터 흐름, 배포 방법을 정리해 기존 프로젝트를 깔끔한 GitHub 포트폴리오로 만들고, LLM 대화 API을 대표작으로 추가하는 구성이 좋습니다.

## 문서 프로그램은 어느 정도 배워야 할까?

문서 도구를 배우는 건 좋지만, 개발 직무의 핵심 스펙은 **문서 프로그램 자격증보다 작동하는 프로젝트와 GitHub 자료**에 더 가깝습니다.

- **Word·한글(HWP):** 과제와 보고서, 프로젝트 설명서를 보기 좋게 작성하는 정도
- **PowerPoint:** 프로젝트 발표, 기능 흐름도, 아키텍처와 결과를 짧게 설명하는 정도
- **Excel:** 표·기본 함수·필터·피벗·차트로 테스트 결과, 응답시간, 비용을 정리하는 정도
- **GitHub Markdown:** README, 설치 방법, API 문서, 개발 기록을 쓰는 정도

따라서 문서 도구는 **프로젝트에서 막힘없이 쓰는 수준**을 목표로 하고, 포트폴리오 시간은 코드를 만들고 설명하는 데 더 많이 배분하는 걸 권합니다. 개발자에게는 잘 정리된 README와 발표 자료가 실력의 근거가 되고, Excel은 AI 응답을 비교·평가할 때 실제로 유용합니다.
