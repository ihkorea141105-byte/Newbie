# 개발 로드맵 — 우선순위와 완료 기준

## 원칙

작은 단위로 구현하고, 각 단계마다 실행 가능한 증거를 남긴다. 완료 상태는 `계획` → `코드 작성` → `로컬 실행` → `테스트 통과` → `외부 API 통합` → `배포`로 나눠 기록한다.

## 1단계 — 응답 검증 모듈을 FastAPI에 연결 (가장 먼저)

작업 위치 예시: `portfolio/2026-11-4/`

- 기존 `portfolio/2026-11-1/try1/app.py` 복사
- `portfolio/2026-11-3/response_validation.py` 복사
- app.py 안의 기존 `LLMResponse` 중복 정의 제거
- `from response_validation import LLMResponse` 추가
- API 폴더에 `requirements.txt` 추가: `fastapi`, `uvicorn[standard]`, `groq`, `pydantic>=2,<3`, `python-dotenv`
- 저장소 루트에 `.gitignore` 추가: `.env`, `.venv/`, `__pycache__/`, `*.py[cod]` 등 제외

완료 기준:
- 검증 모듈 단독 실행 8/8 통과
- 정상 API 요청의 응답 구조 확인
- 잘못된 상태/범위 초과/필드 누락/잘못된 JSON을 Mock으로 주입
- 검증 실패 시 기본 응답과 예제 상태 점수 변화 0이 반환되는지 확인
- 실행 날짜·Python/Pydantic 버전·명령·출력 결과 기록

## 2단계 — 요청/응답 계약과 상태 범위 강화

- `ChatRequest`의 입력 길이와 대화 메시지 수 제한
- history item을 Pydantic 모델로 만들고 `role`/`content` 자료형 제한
- response의 mood도 `Literal`로 제한
- 누적 예제 상태 점수 0~100의 정책(거부 또는 보정)을 정하고 검증
- 예외 메시지에 내부 오류 정보가 노출되지 않도록 변경
- CORS 출처를 개발 프론트엔드로 제한

완료 기준: 정상/비정상 요청을 자동 테스트하고 Swagger `/docs`에서 확인.

## 3단계 — 서버 세션과 영구 저장

- 우선 SQLite로 대화 세션, 메시지, 상태를 저장
- 세션 ID로 이전 대화를 불러와 이어 말하기
- 사용자가 대화를 초기화/삭제하는 기능
- 예제 상태 점수는 서버에서 계산·저장해 클라이언트 임의 변경을 방지
- 이후 서비스 운영 요건이 확인되면 PostgreSQL로 이전 검토

완료 기준: 서버 재시작 뒤에도 지정한 세션의 대화와 점수가 유지되는 통합 테스트.

## 4단계 — 대화 기억 관리

- 우선 최근 대화 N개를 유지하는 단기 기억을 구현
- 오래된 대화는 사실/취향/사건/약속/추측으로 분류해 요약
- 요약 갱신 시점과 토큰 상한 설정
- 요약이 원문 사실을 왜곡하거나 사용자가 말하지 않은 내용을 추가하는지 테스트
- 입력·출력·요약 토큰과 지연 시간을 모두 측정

완료 기준: 20~30턴 QA에서 핵심 정보 회상과 토큰 사용량을 기록. 절감률은 전후 동일 조건 실측 후에만 기재.

## 5단계 — 프론트엔드 및 이미지 연동

- React + TypeScript로 채팅 화면 구현
- 주 응답/보조 설명 표시 방식 분리(보조 설명은 공개 UX 의도를 먼저 결정)
- 로딩, 오류, 재시도, 대화 초기화
- 상태 label → 고정 asset key → 실제 이미지 URL 흐름 구현
- 이미지 파일을 FastAPI static directory 또는 프론트엔드 public asset에서 제공

완료 기준: 브라우저에서 메시지 전송·응답 표시·상태 이미지 변화·오류 처리를 확인.

## 6단계 — 상태 모델 분리 학습

- 프롬프트 설정과 API 코드를 분리
- 독립 상태 변수를 Pydantic 모델과 Enum으로 정의
- LLM이 제안한 변화량은 서버에서 범위와 규칙을 검사
- 사실·추측·미해결 항목을 구분하는 기억 스키마 설계

완료 기준: 세션별 설정과 상태가 독립 작동하는지 검사.

## 7단계 — 서비스 품질·배포

- pytest 기반 단위/통합 테스트
- 로깅에서 API 키·개인정보 제거
- 인증, rate limit, timeout, 요청 크기 제한
- Docker 기초 및 배포 환경 변수 설정
- HTTPS와 허용 CORS 도메인 구성
- 비용/지연/검증 실패율/기억 정확도 지표 수집

완료 기준: 배포 URL, 실행 방법, 테스트 결과, 알려진 제한을 README에 기록.

## 추천 학습 순서

Python 자료형/함수/예외 → Git/GitHub → HTTP/JSON/REST → Pydantic → FastAPI → 테스트(pytest) → SQLite/SQL → React/TypeScript → 배포/Docker → 기억 요약/평가.

Redis, SSE, 비동기 구조, 클라우드 고도화는 실제 병목과 요구가 확인된 뒤 추가한다. 모든 기술을 한꺼번에 도입하지 않는다.
