# AI 응답 도우미 챗봇 개발실 — 프로젝트 컨텍스트

> 목적: LLM API를 활용한 응답 도우미 대화 서비스를 단계적으로 구현하고, 학습·개발·검증 과정을 신뢰할 수 있는 GitHub 포트폴리오로 축적한다.
> 기준 자료: `chatbot-training.zip`에 포함된 자료(기록일 2026-10-31~2026-11-04).

## 1. 학습 프로젝트

초보자가 Python과 LLM API 연동을 학습하고, 코드 작성·분석·검증 과정을 기록하는 프로젝트입니다.
기준 코드는 `portfolio/2026-11-1/try1/app.py`입니다.
Groq 동기 호출, JSON 파싱, Pydantic 검증, 상태 점수 누적과 대화 이력 반환을 학습합니다.
프론트엔드, DB, 인증, 요청 제한, 외부 API 실행 검증은 미완료입니다.

## 3. 날짜별 성장 기록

- **2026-10-31:** `.env`로 API 키를 소스와 분리하는 원칙, 브라우저가 아닌 백엔드 경유 호출 구조, Groq 터미널 실험, 응답 도우미 프롬프트와 상태/기억 설계 방향을 학습했다.
- **2026-11-01:** Groq 대화 코드를 FastAPI REST API로 이동했다. `/api/chat`에서 입력과 대화 이력을 받고, 주 응답·보조 설명·상태·이미지 파일명·예제 상태 점수 변화·갱신된 대화 이력을 반환하도록 작성했다.
- **2026-11-02:** 프로젝트 문서화와 입력·출력 규칙 정리를 학습했다. 시각 자료와 작품 설정은 공개 범위에서 제외했다.
- **2026-11-03:** Pydantic의 `Literal`, `Field(ge, le, strict=True)`를 사용한 검증 모듈을 작성했다. 허용 상태 세 개와 한 번의 예제 상태 점수 변화량 -5~+5를 제한한다.
- **2026-11-04:** 검증 모델의 정의 위치와 사용 위치를 코드에서 확인했다. 기존 FastAPI에 검증 모듈을 연결하고 테스트하는 작업은 계획 상태이며, 기록상 API 연동 및 Groq 호출은 미실행이다.

## 4. 기술 상태 요약

| 기능 | 현재 상태 | 주의할 점 |
|---|---|---|
| Groq 모델 호출 | FastAPI에서 동기 호출 | 실 API 요청 검증은 미확인 |
| 구조화 응답 | JSON mode + `json.loads` | JSON 형식이 맞아도 값 범위는 별도 검증 필요 |
| 응답 모델 | 현재 `app.py` 내부의 기본 Pydantic 모델 | 상태 `str`, 변화량 범위 제약 없음 |
| 별도 검증 모듈 | `response_validation.py` | 현재 API에 import/연결되지 않음 |
| 예제 상태 점수 | 클라이언트 점수 + LLM 변화량 합산 | 0~100 누적 범위 미보장, 클라이언트 조작 가능 |
| 대화 기억 | 클라이언트가 history를 다음 요청에 재전송 | 영구 저장/요약/사용자별 세션 없음 |
| 이미지 | 상태별 PNG 파일명 반환 | 파일 URL/정적 파일 서버/프론트엔드 연결 없음 |
| UI | 없음 | React 등 미구현 |
| 배포·성능 | 미검증 | 수치나 절감률 주장 금지 |

## 6. 개발 시 지켜야 할 기준

1. 항상 **기획됨 / 코드 작성됨 / 로컬 테스트됨 / 외부 API 통합 테스트됨 / 배포됨**을 구분해 기록한다.
2. AI가 제안한 아키텍처·샘플·목표 수치·이력서 문장은 실행과 측정 없이 구현 성과로 올리지 않는다.
3. 기존 파일을 덮어쓰지 않는다. 날짜별 작업 폴더나 Git 브랜치에서 변경하고, 변경 이유와 테스트를 기록한다.
4. API 키는 `.env`에만 두고 Git에 커밋하지 않는다. 실제 키는 채팅·README·로그에 붙여넣지 않는다.
5. 초보 개발자가 코드를 직접 이해할 수 있도록 변경 파일·변경 위치·실행 명령·예상 결과·오류 해결을 설명한다.
7. 성능·토큰 비용·기억 정확도 등은 측정 조건과 표본을 기록한 후에만 수치로 주장한다.

## 7. 지금 이어서 할 일

가장 먼저 `portfolio/2026-11-4/README.md`에 적힌 계획을 실제 작업으로 완성한다.

1. 기존 `app.py`를 새 작업 폴더에 복사하고 `response_validation.py`도 함께 둔다.
2. `app.py` 안의 중복 `LLMResponse` 정의를 제거하고 검증 모듈에서 import한다.
3. 정상·경계·잘못된 상태·범위 초과·문자열 숫자·불리언·필드 누락·잘못된 JSON을 테스트한다.
4. 실제 Groq 호출 없이 잘못된 응답을 주입하여 기본 응답 처리까지 확인한다.
5. 그 다음 요청/응답 스키마, 누적 점수 범위, 대화 이력 제한, 오류 응답과 보안을 개선한다.
